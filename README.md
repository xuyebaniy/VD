# Ваш Доктор — демоверсия PWA

Приложение: https://xuyebaniy.github.io/VD/

Это рабочая демонстрация родительского кабинета, отдельных детских садов здоровья и кабинета врача. SMS, медицинские документы, обмен с медицинской системой и удалённые пуш-напоминания не подключены.

**Обновление 24 ноября 2026:** подготовлены регистрация родителя по электронной почте, API и серверный модуль для клиники. Отправка писем в опубликованной GitHub-версии **не включена**: в `cabinet-config.js` пустой адрес API. Форма сообщает об этом и не отправляет запросов, не создаёт локальных кодов и не сохраняет введённые контактные данные. Для проверки дневника доступны отдельные демосемьи.

Адрес `/VD/`, `manifest.id: "./"`, `scope: "./"`, установочная иконка и оригинальные изображения сохранены. Обновление получает то же установленное приложение; переустановка не требуется.

## Кабинет принадлежит родителю

На первом экране выберите «Демосемья» или создайте свою демосемью. В исходной семье есть два вымышленных ребёнка с пустыми дневниками: Миша и Аня. Новая семья создаётся без детей.

Родитель добавляет ребёнка по имени; дата рождения необязательна. Ребёнок не получает отдельный логин или самостоятельный кабинет. Внутри родительского кабинета каждому ребёнку принадлежит отдельный «Сад здоровья», история дневника и индивидуальные рекомендации.

Можно выбрать день, поставить обычные галочки «Выполнено» для питания, воды, движения, сна, экранного времени и пункта о самочувствии, добавить заметку и нажать «Сохранить день». Для частичного выполнения и невыполнения сохранены отдельные варианты. Повторное нажатие снимает отметку. До сохранения изменения остаются черновиком. Будущие даты и даты до рождения ребёнка недоступны. Мама и ребёнок могут заполнять дневник вместе в родительском кабинете.

## Вход по электронной почте

После установки серверного модуля на хостинг клиники:

1. Новый родитель выбирает «Регистрация», указывает ФИО, электронную почту и телефон.
2. На почту приходит одноразовый шестизначный код. Телефон используется как контакт и на этом этапе не подтверждается.
3. Родитель вводит код и получает собственный кабинет. При повторном входе достаточно почты и нового кода.
4. Родитель добавляет детей; каждому принадлежат отдельный дневник и рекомендации. Самостоятельной регистрации ребёнка нет.

Проверка кода, создание аккаунта, хранение дневников и проверка доступа выполняются сервером. Browser API не создаёт кодов и не хранит токены, ФИО или ответы кабинета в localStorage/Cache Storage. Токен живёт в памяти до выхода, перезагрузки или истечения серверной сессии. При завершении сессии экран и черновики очищаются. Демоданные не переносятся в настоящий кабинет автоматически.

Серверный пакет и порядок подключения: [integration/patient-cabinet/INSTALL.md](integration/patient-cabinet/INSTALL.md). Необходимы сервер клиники, закрытое хранилище и SMTP-доступ служебной почты. Пароли и ключи задаются только на сервере вне публичной папки и репозитория. PHP-файлы и конфигурация сервера не входят в Pages-артефакт.

## Демокабинет врача

На стартовом экране нажмите «Открыть демокабинет врача». Если открыта семья, сначала выберите «Мой кабинет» → «Выйти и сменить кабинет».

Врач видит **только прикреплённых детей**, сохранённых в этом же браузере на этом же устройстве. Исходные демопрофили Миши и Ани прикреплены к демоврачу; новые дети по умолчанию не прикреплены. Проверка действует и при запросе отдельного дневника, и при изменении рекомендаций. Для выбранного ребёнка доступны:

- Динамика заполненных отметок по дням и за выбранный месяц.
- Процент выполнения отдельно по каждой из шести рекомендаций.
- Полнота заполнения дневника и дни без отметок.
- Индивидуальные текстовые рекомендации по каждому направлению. После сохранения они видны родителю в саду и рядом с отметками дня.

Врач меняет рекомендации, но не редактирует внесённые родителем отметки. Готовых лечебных назначений, возрастных норм или медицинских заключений демоверсия не создаёт.

Настоящий доступ врача отделён от родительского. SMS-аутентификация отложена: серверные методы входа врача возвращают недоступность и не выдают сессий. Структура ролей, таблица прикреплений и проверка доступа к своим пациентам уже предусмотрены. Создать врача и прикрепить ребёнка может администратор клиники через серверную CLI; родитель не назначает себе врача и не получает его роль через форму регистрации.

### Как считается процент

«Выполнено» даёт 100%, «Частично» — 50%, «Не выполнено» — 0%. Процент дня, месяца или отдельного направления — среднее по **заполненным** отметкам соответствующего периода. Дни и пункты без отметки не считаются невыполненными. Если отметок нет, показывается отсутствие данных, а не 0%. Будущие дни не входят в месячные итоги.

Полнота заполнения показывается отдельно. Например, один выполненный пункт даёт 100% по этому пункту при заполнении 1 из 6 пунктов дня. Эти значения отражают записи в дневнике и выполнение рекомендаций, а не состояние метаболического здоровья.

## Хранение демоданных

Семьи, дети, дневники и рекомендации сохраняются в localStorage этого браузера под версионным ключом `vd_cabinet_demo_v1`. Это демонстрационное переключение ролей, **не настоящая авторизация**. Любой пользователь этого браузера может открыть демосемью или кабинет врача. Используйте вымышленные данные.

После перезагрузки записи сохраняются, но снова предлагается выбор кабинета. Очистка данных браузера удалит демоданные. Другой браузер или устройство имеют отдельное хранилище; обмен между устройствами не настроен. Если браузер запретил постоянное сохранение или квота исчерпана, приложение продолжает работать в памяти и сообщает, что изменения доступны только до закрытия страницы. Повреждённые сохранённые данные не перезаписываются.

Для совместной работы настоящих родителей и врачей на разных устройствах потребуется развернуть подготовленный серверный модуль и позднее включить отдельную SMS-аутентификацию врача. Опубликованная демоверсия таких подключений не делает.

## Публичные разделы

- Каталог и фотографии врачей берутся с официального сайта клиники. Последний проверенный каталог и изображения включены в сборку.
- GitHub Actions обновляет публичный каталог каждые три часа; есть ручное обновление в интерфейсе.
- В окне записи отображается только штатный виджет Medihost клиники `48196`: направления, врачи, календарь и последующие шаги записи. `booking-widget.html` загружает официальный JavaScript-модуль; полная страница сайта клиники, её шапка, логотипы и меню не встраиваются.
- Во время загрузки показан короткий статус. После появления настоящих элементов расписания он исчезает. Кнопка повторной попытки появляется только при задержке, ошибке или отсутствии сети и перезагружает только iframe. Постоянных внешних ссылок и дополнительных пояснений над виджетом нет; звонок остаётся в штатной верхней панели приложения.
- Пока окно записи открыто, обновление каталога не пересоздаёт его, а активация нового Service Worker не перезагружает страницу автоматически: введённая в форме информация сохраняется. Ручная перезагрузка окна или уход со страницы записи начинают выбор заново.
- В верхней панели доступен звонок в клинику: +7 (484) 220-05-40.
- «Медицинские документы» и переписка с оператором показывают, что подключение будет сделано позже. Они ничего не загружают и не отправляют.
- Новые внешние сервисы, SMS или отправка пушей не подключены.

В этой демоверсии Medihost подключён как доверенный сторонний JavaScript на том же origin, что и приложение. `allow-same-origin` сохраняет корректные параметры CORS и доступ к cookie, которые нужны официальному загрузчику. Sandbox ограничивает часть возможностей окна, но **не изолирует сторонний код от DOM и localStorage родителя**. Оболочка приложения не передаёт в виджет профили, дневники или рекомендации; сообщения между окном и приложением содержат только состояние загрузки и высоту. Это не защита от произвольных действий доверенного стороннего скрипта. Перед подключением настоящих медицинских данных виджет следует перенести на отдельный origin, сохранив тот же компактный интерфейс.

Режим настоящего кабинета требует API на том же защищённом origin, что и кабинет, и виджет записи на отдельном origin. `cabinet-api.js` отказывает в активации при нарушении этого условия и на `github.io`. Внешнему окну передаётся только публичный origin родителя; обратные сообщения проверяются по origin, источнику и точной схеме. Виджет в приложении сохраняет компактный вид.

Для размещения настоящего кабинета используется отдельный сборщик `scripts/stage_clinic.py` из инструкции установки. Он исключает `booking-widget.html` со всего приватного origin, генерирует публичные адреса подключения и отдельный Service Worker, не меняя исходную демоверсию. Размещение публичной сборки целиком на origin кабинета недопустимо: доступный там сторонний виджет позволил бы обойти разделение через вложенное окно.

Service Worker кеширует только разрешённые публичные файлы, каталог и фотографии. После первого открытия с интернетом локальные демосценарии и сохранённый каталог доступны офлайн. Код серверных интеграций, тесты и служебные файлы не входят в публичный Pages-артефакт.

## Проверка демонстрации

1. Откройте семью, выберите ребёнка, заполните и сохраните день.
2. Переключитесь на второго ребёнка: его дневник независим.
3. Выйдите, откройте демокабинет врача и выберите первого ребёнка.
4. Посмотрите проценты дня и месяца; сохраните индивидуальную рекомендацию.
5. Выйдите из кабинета врача и снова откройте нужную семью: рекомендация появится у соответствующего ребёнка.

## Разработка и повторяемые проверки

- `cabinet-demo.js` — локальное хранилище, демосессии, разделение возможностей родителя и врача.
- `cabinet-config.js` / `cabinet-api.js` — публичная конфигурация и транспорт реального API; по умолчанию выключены.
- `patient-cabinet.js` / `.css` — вход в демоверсию, родительский кабинет и дневник в существующем дизайне.
- `doctor-cabinet.js` / `.css` — динамика, расчёт процентов и индивидуальные рекомендации.
- `scripts/stage_public.py` — сборка разрешённых публичных файлов в `_site/`.
- `tests/demo-adapter.cjs` — изоляция семей и детей, хранение, частичные изменения, права ролей.
- `tests/demo-stats.cjs` — расчёт процентов, отсутствие данных, будущие дни и месячные итоги.
- `tests/demo-ui.cjs` — Playwright: реальные пользовательские действия, перезагрузка, роль врача, сохранение рекомендаций, узкий экран. Внешняя сеть в тестах заблокирована.
- `tests/booking-embed.cjs` — Playwright: корректный origin и CORS загрузчика, компактный интерфейс, состояния загрузки и восстановления, проверка источника сообщений и сохранение формы при фоновых обновлениях. Провайдер подменяется контролируемой тестовой реализацией; тест не оформляет реальных записей, не проверяет свободные приёмы у Medihost и не заявляет изоляцию same-origin окна от родителя.
- `tests/demo-dom.cjs` — те же основные сценарии через JSDOM без проверки отрисовки.
- `tests/cabinet-cache.cjs` — границы публичного кеша и удаление старых кешей.
- `tests/cabinet-api.cjs` — настройки origin, отсутствие локальных OTP, транспорт, маскирование ошибок и тайм-ауты.
- `tests/email-auth-ui.cjs` — регистрация, код, изоляция данных, истечение сессии и отмена входа с подставным API без реальных писем.
- `integration/patient-cabinet/tests/` — одноразовые коды, лимиты, шифрование, серверные роли, прикрепления и HTTP-границы.
- `tests/clinic-build.py` — приватная сборка без локального виджета, небезопасных адресов и перезаписи существующего каталога.

Основные команды:

```sh
node tests/demo-adapter.cjs
node tests/demo-stats.cjs
node tests/cabinet-cache.cjs
node tests/cabinet-api.cjs
# При установленном jsdom:
node tests/demo-dom.cjs
node tests/email-auth-ui.cjs
# При запущенном локальном HTTP-сервере и установленном Playwright/Chromium:
VD_BASE_URL=http://127.0.0.1:8765 node tests/demo-ui.cjs
VD_BASE_URL=http://127.0.0.1:8765 node tests/booking-embed.cjs
```

GitHub Actions запускает проверки адаптера, кеша и браузерных сценариев перед публикацией и сохраняет снимки интерфейса как артефакт. Для получения обновления закройте установленное приложение и откройте снова с интернетом. Во время открытого демокабинета автоматическая перезагрузка при обновлении Service Worker откладывается.
